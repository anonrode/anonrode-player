# Baseline Profile (HRF — Human Readable Format) for dev.anonrode.player
# -----------------------------------------------------------------------
# Format reference: https://developer.android.com/topic/performance/baselineprofiles
# -----------------------------------------------------------------------
# Each non-comment line is one of:
#   L<class>;                                  -> pin the whole class
#   [H][S][P]L<class>;-><method>(<params>)<rt> -> pin a specific method
#   [H][S][P]L<class>;-><method>:<fieldType>   -> pin a field accessor
#
# The flag prefixes (H = hot, S = startup, P = post-startup) are ART
# optimisation hints. We default to class-level rules (no flags) which
# tell ART: "this class is in the startup / hot path, AOT-compile it".
# Method-level rules are added only where we know a specific call site
# is on the hot path (e.g. PlayerScreen recomposition, gesture handlers,
# ExoPlayer internals reached on the first frame).
#
# HONESTY NOTE — Aug 2026:
# This profile was authored manually, NOT generated by AGP / R8 /
# Macrobenchmark. The class list is drawn from a parent-led static
# inspection of the critical user journeys (cold start → Library →
# open video → PlayerScreen → gesture → return to Library → open
# Settings). Method-level lines are conservative and based on the
# known-hot entry points of Media3 1.11.0 and the app's own onCreate
# surface. The integrator (parent agent) MUST regenerate this with
# the canonical tooling (`./gradlew :app:generateBaselineProfile`)
# before shipping — every interaction measured there that lands a
# method-level rule here is a real production trace; everything
# else is educated guesswork.
# -----------------------------------------------------------------------
