Design proposal · v0.9

Single-Plane Chrome

Today's player runs two header rows plus a three-cluster bottom dock — roughly eleven controls competing for the same glance — while the flagship feature (sub-sync) is reduced to one pill among six, and subtitle styling hides inside a modal sheet. This proposal collapses all of it into one auto-hiding plane with three zones: Transport → Context → Everything else. Nothing is removed from the feature set; it is re-ordered by how often a thumb actually needs it.

State 2 · plane open
One plane, three zones.
Zone 1 — Transport. The five controls a thumb hunts for, alone in the centre, at full token size (play 64 dp, skips 48 dp). Screen-lock moved out of this row: it is a mode, not transport, so it now leads the rail.
Zone 2 — Status. Sync state, speed and remaining time as a thin read-out line, not buttons. This is the single biggest change: sub-sync stops being one pill lost among six and becomes the thing you can see working.
Zone 3 — Rail. One scrollable row that replaces the old permanent quick-tools ribbon and the redundant bottom utility dock. Grouped by a divider: playback modifiers left, output/route right.
  • Top bar drops from two rows to one
  • HW/SW decoder pill leaves the header for Control Centre
  • Every hit area ≥ 48 dp (the old ribbon chevron was 36 dp)

State 6 · landscape
Edge rails for the rare controls; centre for transport.
Widescreen auto-lands you here (the onVideoSizeChanged listener). Instead of a top ribbon stacked over a bottom dock, secondary controls move to left/right edge rails — inside the letterbox black bars on a 16:9 source, so they cost zero video height. Centre stays exactly what your thumb expects: seek, then transport.
  • Left rail: sync + lock (the two state controls)
  • Right rail: speed + rotate + PiP
  • Subtitles never sit under a control zone

02 What actually changes

Nothing is deleted from the feature set. It is re-ordered by frequency of use, and three duplicate surfaces collapse into one. Evidence citations refer to the 09-19 device log (936 lines).

Current surfaceThe problemv0.9 treatment
Row-2 quick-tools ribbon
6 pills + 36dp chevron		 Permanent, dense, six equal-priority controls. The chevron is a 36 dp hit target with a dimmed 0.75-alpha tint — reads as disabled and smaller than the tools it reveals. Becomes the contextual rail (grouped by divider). The chevron is rebuilt to touchMin = 48dp, same idle tint and glyph as every chip.
Bottom utility dock Duplicates tools already in row 2 — two homes for the same controls, so a user must remember which is canonical. Deleted. One home per control: transport in the centre, everything else in rail or sheet.
HW/SW pill in the header A low-frequency decoder toggle spends prime header space; its current state is invisible without a tap. Moves to Control Centre under Playback, and shows its state inline (HW).
Sync popover + bottom sync chip The flagship feature is one pill among six. You cannot tell whether it worked without opening the popover. The 09-19 log is you hunting for that answer. Sync becomes a status read-out — green/amber/grey dot + offset — always visible when the plane is open. Tapping it opens an inline tray with offset, speed, confidence and source.
SubtitleStyleSheet modal Modal blocks the frame while you adjust the one thing the log shows you touch most (~40 style edits in a single session). Inline style tray. Subtitle preview stays live while you change position / size / colour / weight.
Overflow sheet Grab-bag with no grouping; sleep timer and stats buried among unrelated controls. Becomes the grouped Control Centre: Playback · Tools · Session · Output.
Old right-edge rail v0.7.3 already removed it for duplication. Stays removed. Landscape uses edge rails instead, but only inside the letterbox bars.

03 Interaction grammar

Every control follows the same tap / long-press grammar already in the app — nothing new to learn. The redesign is a re-skin of existing PlayerScreenActions, not a behavioural rewrite: the same methods (togglePlayPause, resyncNow, setSubSyncEnabled, cycleRotateMode…) are just mounted differently.

04 Migration

This is not a rewrite. It is a re-parenting of existing composables and a rebuild of two (PlayerSubSyncToggle, PlayerScreenSheets) into inline surfaces. The sync engine and the playback engine are untouched — everything below is presentation.

FileVerdictWhy
PlayerScreenControls.ktReworkDrop Row 2 entirely; keep the single header row (back / title / CC / audio / ⋮).
PlayerScreenBottomBar.ktReworkKeep the 14dp thumb and 3-cluster transport; remove the redundant utility dock; move speed/aspect to rail; add the status strip.
PlayerSubSyncToggle.ktRebuildBecomes the status pill + inline sync tray (the popover model goes away).
PlayerScreenSheets.ktRebuildStyleSheet + overflow sheet become the inline style tray and the grouped Control Centre.
PlayerScreen.ktWireRe-parent the tray/sheet open-state to the new zones; add the idle progress hairline.
PlayerDimens.ktUnchangedThe proposal consumes every existing token; nothing new to add.

What I would do next

  1. Implement this on a branch (ui/single-plane-chrome), off the v0.8.7 sync fixes already staged.
  2. Let the new CI test gate run against the branch before any UI lands on main.
  3. Keep the v0.8.6 chrome behind a flag for one release so a visual regression can be flipped back without a rollback.
  4. On-device check the six states against the real PlayerDimens scale — the mockups are 1:1 with those values, so what you see is the intended density.
