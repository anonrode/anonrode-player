Anonrode Player — Player Screen

Exact-match mockup of the landscape player overlay, rebuilt from the reference captures in C:\Users\user\Downloads\ (Screenshot_20260925-214414.jpg, …-214409.jpg, …-214350.jpg, …-140005.jpg) and the screen recording screen-20260925-214743.mp4.

The captures are 1612×720 px, i.e. 873×393 dp at 1.846 px/dp. Every offset in the CSS was measured off the native-resolution image by cropping strips and scanning raw pixel rows and columns for the first and last non-black sample. Sizes marked in the comments come from the Compose source, which is the authority for anything inside a component.

  • FIT (RESIZE_MODE_FIT) — whole frame visible, never cropped. On a 16:9 source inside the 873×214 dp stage this is height-constrained: 380×214 dp, pillarboxed with black either side.
  • CROP (RESIZE_MODE_ZOOM) — fills the stage, centre-cropped.
  • STR (RESIZE_MODE_FILL) — stretches to the stage, distorted.
  • 16:9 / 4:3 — forcedAspect != null, so the surface Box is locked with Modifier.aspectRatio() and the frame is stretched to fill it.

1 — Default: FIT, ribbon at rest

Opening state. The whole frame is visible and pillarboxed; the ribbon sits at scroll offset 0 with all thirteen tools visible, which is what the recording shows at 00:07 and 00:13. The Audio Effect chip carries the red hasActiveDot marker because the effect is engaged.

2 — Reference capture: forced 16:9, ribbon already scrolled

This is the frame in Screenshot_20260925-214414.jpg. Two things are worth calling out, because both contradict the naive reading of the screen:

  • The video is small. The measured picture box is 390×219 dp at x 242, y 75 — exactly 16:9, but nowhere near the 873 dp width. The surface is aspect-locked inside the stage rather than filling the frame, so the picture is letterboxed on all four sides. This is the “not fullscreen because the aspect was changed” case, not a bug.
  • The ribbon is clipped on the left and empty on the right. The moon is cut in half at x 0 while the last tool ends at x 736 with 137 dp of clear space behind it. That is a retained scroll offset — the ribbon was dragged and the position stuck.

3 — The ribbon is a real horizontal scroller

Drag the ribbon, use the wheel over it, or move the slider. The offset is clamped to max(0, track − viewport), exactly as Compose clamps ScrollState.

Across this 873 dp window the track is 806 dp — thirteen tools at widthIn(min = 56.dp) plus 4 dp spacing, then the trailing “more” chevron — which fits. So in landscape the scroll range clamps to 0 and the ribbon genuinely cannot move. It overflows the moment the window is narrower, which is why the portrait scene below is the one with a real scroll range, and why the capture in scene 2 can only have come from a build with a wider pitch, a larger minimum cell, or more tools enabled. The recorded swipe at 00:04 and 00:17 is that same overflow in action.

4 — Transient HUD and lock

Tapping the aspect button cycles the zoom and raises the HUD toast for a moment. With the lock engaged the transport stays lit but taps stop reaching the surface, and the note appears along the bottom.

5 — Portrait, where the ribbon overflows

411×893 dp. The stage is 411×420, so a 16:9 frame is width-constrained at 411×231 dp, and the 806 dp ribbon overflows a 411 dp window by 395 dp — a real scroll range, with the tail of the list reachable by swiping.
