# Anonrode Player — Engineering Audit

Date: 2026-08-27 · Scope: full Kotlin source tree (app/, core/, feature/), read-only · Tools skipped per instruction.

Note: the tree was actively being edited during this audit (PlayerActivity.kt grew 895→983 lines and `SubtitlePickerSheet.kt` appeared mid-audit). Line numbers below reflect the state at ~21:52 local time. The subtitle-playback path now correctly honors `subtitleChoice` via `SubtitleSourceResolver` — findings are written against that current state.

---

## Top 5 do first

1. **[P0] Sidecar subtitles are invisible on Android 13+** — with only `READ_MEDIA_VIDEO` granted, the `MediaStore.Files` queries that resolve `.srt/.ass` sidecars return nothing on API 33+, silently disabling the headline sync feature on most modern devices. (`SubtitleSourceResolver.kt:93-130`, `AndroidManifest.xml:59-62`)
2. **[P0] Probable compile error in the current tree** — `PlayerPrefs.globalSpeed(this)` at `PlayerActivity.kt:510` sits inside `lifecycleScope.launch(Dispatchers.IO){…}`, where `this` is a `CoroutineScope`, not the `Context` the function requires. Use `this@PlayerActivity`.
3. **[P1] Room read-modify-write clobbering** — every `MediaStateStore` writer does `get()` + whole-row `copy()` + `upsert()`; concurrent writers (position saves, live auto-sync lock, nudges, speed, fingerprint job) overwrite each other's fields. (`MediaStateStore.kt:26-105`, `AnonrodeApp.kt:43-47`)
4. **[P1] Overlapping `openVideo` coroutines race on episode switch** — nothing cancels or serializes the per-open IO coroutine, so rapid Next/Next (or a subtitle-choice reload) can let a stale open win `engine.play` + render loop + queue. (`PlayerActivity.kt:459-537`, `869-883`)
5. **[P1] Live sync dies after ~16.3 min of media** — `AudioSyncProcessor.audioBins` is a fixed 9800-bin (100 ms) array; any resume position beyond ~16:16 (or playback past it without a lock) skips `evaluate()` forever, silently disabling the live lock for most of a normal episode. (`AudioSyncProcessor.kt:34`, `176-194`)

## P0 — ship-blockers

### 1. Sidecar subtitle resolution broken on API 33+ (verify on-device first)
`SubtitleSourceResolver.listSidecars` (`core/media/.../subtitle/SubtitleSourceResolver.kt:93-130`) queries `MediaStore.Files` with `DISPLAY_NAME LIKE '%.srt' …`. The manifest declares only `READ_MEDIA_VIDEO` plus `READ_EXTERNAL_STORAGE` capped at `maxSdkVersion=32` (`app/src/main/AndroidManifest.xml:59-62`). On Android 13+ each `READ_MEDIA_*` permission exposes only its own collection — non-media files (subtitles) in `MediaStore.Files` are not visible, so the query returns zero rows and `openInputStream` on any hand-found URI would throw `SecurityException`. Impact: playback shows no sidecar cues and `SyncFingerprintJob.findSidecarSubtitle` (`SyncFingerprintJob.kt:219-286`) finds nothing → the entire sidecar sync pipeline is dead on modern devices. The legacy copy in `PlayerActivity.findSidecarSubtitle` (`PlayerActivity.kt:904-965`, now dead code) has the same flaw.
Fix options: SAF tree pick (the manifest already declares an `OPEN_DOCUMENT_TREE` queries block and `MediaScanner.applyFolderFilter` hints this was planned), or `MANAGE_EXTERNAL_STORAGE` for a personal sideloaded app. Verify with a 33+ device/emulator before anything else.

### 2. `this` type mismatch inside coroutine (build break as audited)
`PlayerActivity.kt:510`: `PlayerPrefs.globalSpeed(this)` inside `lifecycleScope.launch(Dispatchers.IO) { … }` — the lambda's receiver is `CoroutineScope`; `globalSpeed` takes `Context` (`PlayerPrefs.kt:40`). If this tree is what you last built, it does not compile; fix with `this@PlayerActivity`. (May be transient mid-edit state — re-check.)

## P1 — soon

### Correctness / races

### 3. Room read-modify-write clobbering (data loss: resume positions, sync locks)
Every writer in `MediaStateStore` (`core/media/.../state/MediaStateStore.kt:26-105`) is `dao.get(uri)` → `cur.copy(field=…)` → `dao.upsert(cur)` — a full-row copy. Writers run concurrently from different scopes:
- position saves every `savePositionNow`/`persistPositionNow` (`PlaybackEngine.kt:385-402`) from the engine scope,
- live sync lock as **two sequential RMWs** `updateAutoSyncOffset` then `updateAutoSyncSpeed` (`AnonrodeApp.kt:43-47`, fired from `PlaybackEngine.onSyncLocked:236-245`),
- nudge writes per button tap (`PlayerActivity.kt:310-318` — rapid taps launch overlapping coroutines),
- speed writes (`PlayerActivity.kt:272-284`),
- fingerprint job's `updateAutoSync` (`SyncFingerprintJob.kt:141`).
Interleaving loses fields: a position save that read the row before a sync-lock write will upsert its stale copy and revert the lock (and vice versa). Today the window is narrow because the 5 s autosave loop never runs (finding 8); once you start the service this becomes a steady clobber.
Fix: partial-column `@Query("UPDATE media_state SET … WHERE uri=:uri")` per field (with `@Insert(onConflict=IGNORE)` bootstrap), or a single `withTransaction { get; upsert }` plus a mutex per URI.

### 4. `openVideo` coroutines are never cancelled or serialized
`PlayerActivity.openVideo` (`PlayerActivity.kt:459-537`) launches a fresh `lifecycleScope.launch(Dispatchers.IO)` per call; `currentUriStr` is set synchronously at :462 but `engine.play`, `restartRenderLoop`, `episodeQueue =` happen whenever that coroutine's IO finishes. Two fast episode switches (or a subtitle-choice reload via `onSubtitleChoiceSelected:869-883`, which doesn't even set `switching`) run in parallel; the **last to finish wins**, which may be the episode the user switched away from — while `currentUriStr` (the persistence target for speed/nudges) already points at the newer one.
Fix: keep the `Job`, `cancel()` it at the top of `openVideo`, and/or guard with a generation counter checked before the `withContext(Dispatchers.Main)` commit.

### 5. Live sync disabled past ~16.3 minutes (fixed bin array)
`AudioSyncProcessor.kt:34`: `audioBins = FloatArray(40*10*2 + 15*60*10)` = 9800 × 100 ms = 980 s. `accumulateBin` (`:176-194`) computes `idx = posMs/100` from the absolute media position and **returns before `evaluate()`** when `idx >= size`. Consequences: resuming any video beyond ~16:16 never locks (bins never fill, `binCount` stays 0); even from a cold start, content that doesn't lock inside the first 16 min never gets another chance. Fix: index bins relative to `startPositionMs` (ring buffer), or grow/slide the window.

### 6. Heavy correlation runs on the audio render thread
`AudioSyncProcessor.queueInput → analyze → evaluate` (`AudioSyncProcessor.kt:90-102, 196-213`) calls `SpeechCorrelator.findOffset` (`SpeechCorrelator.kt:49-159`): ~801 shifts × `binCount` plus a cross-half pass — up to ~10M+ ops per call, invoked every 1.4 s of audio, **forever** on content that never passes the lock gates. This runs inside Media3's audio sink thread → underrun/skip risk on mid-range devices. Fix: publish the bins to a worker (single-flight), cap attempt count, and/or stop evaluating after N refusals.

### 7. Piecewise lock vs live lock inconsistency (cut content)
The render loop prefers in-memory `piecewiseSegments` over the engine's live offset (`PlayerActivity.kt:819-821`), but a live re-lock persists only scalar offset/speed (`AnonrodeApp.kt:45-46`) and never clears/updates `autoSyncPiecewise`; the SYNCED chip shows `engine.subtitleOffsetMs` (`PlayerActivity.kt:825`) which is **not** the offset actually applied on cut content. DB ends self-inconsistent after any live refinement. Fix: when live lock lands, clear piecewise (or re-derive it), and make the chip report the applied offset.

### 8. `PlayerService` is never started — autosave, notification and media session are dead code
There is no `startService`/`startForegroundService` anywhere in the tree. Therefore:
- the 5 s position-autosave loop (`PlayerService.kt:66-75`) never runs — a process kill loses all progress since the last activity destroy/switch (`PlayerActivity.kt:703,781,879,973`);
- no notification/`MediaSession` is ever published (`PlayerService.kt:49-63`), so no lock-screen controls and no foreground-service protection for background/PiP audio — the system can kill playback at will;
- `PlaybackEngine.stopAndSave()`/`release()` (`PlaybackEngine.kt:404-422`) are never called either.
Fix: `startForegroundService` when playback starts (or on first play), stop/pause it sensibly; this is also the prerequisite that makes finding 3 urgent.

### 9. Back button leaves audio playing with no UI
`onBack = { finish() }` (`PlayerActivity.kt:270`) destroys the activity but the app-scoped engine keeps playing (`onDestroy:967-982` only saves position and removes listeners). The user lands in the library with audio continuing and no controls. Decide: stop the engine on finish, or hand off to the (currently never-started) service with a notification.

### 10. `singleTask` PlayerActivity has no `onNewIntent`
Manifest: `launchMode="singleTask"` (`AndroidManifest.xml:91-96`). When the activity already exists (PiP dismissed to background, Home, or back-to-library without destroy), tapping another video routes to `onNewIntent` — not overridden — so the new URI is ignored and the old video keeps playing. Fix: override `onNewIntent`, update `intent`, re-run `openVideo`.

### 11. Missing `INTERNET` permission — online subtitle search cannot work
`OpenSubtitlesClient` opens `HttpURLConnection` (`core/media/.../subtitle/OpenSubtitlesClient.kt:165`) but no module manifest declares `android.permission.INTERNET` (only manifest: `app/src/main/AndroidManifest.xml:59-65`). Every search/download throws and is swallowed (`SubtitlePickerSheet.kt:100-147` shows a generic note). One-line manifest fix.

### 12. Screen turns off during playback
Nothing sets `FLAG_KEEP_SCREEN_ON` (grep finds only the DataStore field `PlayerSettings.kt:19`), and media3 1.11 `PlayerView` has no built-in keep-screen-on (verified against the library source). The `keepScreenOn` setting is never read. For a video player this is a basic-functionality gap: `window.addFlags(FLAG_KEEP_SCREEN_ON)` in `PlayerActivity.onCreate` (honor the setting while you're there).

### 13. `isSpeakerphoneOn` without `MODIFY_AUDIO_SETTINGS` → crash on tap
`PlayerScreen.kt:977-989` (`cycleAudioOutput`): `audioManager.isSpeakerphoneOn = …` requires `MODIFY_AUDIO_SETTINGS` (not declared) → `SecurityException` on click, uncaught. It also does nothing useful for the music stream — delete the setter, keep the toast, or route through the MediaRouter picker you already have.

### 14. Settings that are editable but never applied
`PlayerSettings` fields `resumeBehavior`, `autoSyncEnabled`, `seekIncrementSec`, `doubleTapSeek`, `swipeToSeek`, `volumeGesture`, `brightnessGesture`, `backgroundPlayback`, `subtitleSize/Position/Bold`, `autoHideControlsMs` (`core/datastore/.../PlayerSettings.kt:14-38`) are written by `SettingsScreen` but read nowhere in playback code (only `autoAdvance` is consumed, `PlayerActivity.kt:706`). Notably: resume **always** resumes (no ALWAYS_ASK prompt), seek buttons hardcode ±10 s (`PlayerScreen.kt:1090-1095,1206`), and the auto-sync engine ignores `autoSyncEnabled`. Wire them or strike the rows.

## P2 — nice

### Leaks / lifecycle
15. `PlayerScreen.kt:914-939`: `hideHud`/`clearTransientToast` are **new Runnable instances per recomposition**, so `view.removeCallbacks(hideHud)` never cancels previously posted ones — the "single hide runnable" guarantee in the comment is broken (HUD can hide early), and nothing cleans them up on dispose. Hoist into `remember { Runnable { … } }`.
16. Sleep timer captures a stale player: `LaunchedEffect(sleepTimerEndMs)` (`PlayerScreen.kt:857-869`) closes over `livePlayer`; after a decoder rebuild, `pause()` at expiry hits the released ExoPlayer → `IllegalStateException`. Key on `livePlayer` or read `engine.player` fresh.
17. Same class of hazard: `DisposableEffect(livePlayer)` cleanup (`PlayerScreen.kt:871-912`) calls `removeListener` on the player that `PlaybackEngine.rebuild` already released (`PlaybackEngine.kt:315-317`); verify media3 1.11 tolerates it, or guard with an `isReleased`-style flag.
18. `PlayerService` adds a rebuilt-hook per `onCreate` and never removes it (`PlayerService.kt:55-63`) — after a service restart, stale hooks build MediaSessions against a dead service context. Also, when `onCreate` bails early on missing holder wiring (`:41-45`) the service never self-heals (no session/autosave until restarted).
19. Render loop never pauses: the 100 ms tick runs until `onDestroy` (`PlayerActivity.kt:807-831`), including STATE_ENDED and while the activity is merely stopped — wasted CPU/battery; pause on `onStop` (except PiP).
20. `AppLog` (`core/media/.../log/AppLog.kt`): every batch does 2 MediaStore queries + an output-stream open (`:84-125`) — constant binder/IO churn during playback; the shared `SimpleDateFormat` (`:35`) is used from many threads (not thread-safe → corrupt lines/rare throws); and the full log (video paths, subtitle names) lands in public `Download/AnonPlayer/`. Move to app-private file, batch harder, use a thread-safe formatter.

### Correctness (lower impact)
21. `updatePosition` clobbers stored duration with `null`: `capturePositionSnapshot` returns `dur=null` when unknown (`PlaybackEngine.kt:374-382`) and `MediaStateStore.updatePosition:26-36` copies it unconditionally — the "don't clobber good duration" comment's intent is defeated; keep the old value when the new one is null.
22. `SyncFingerprintJob` catch-all → `Result.retry()` (`SyncFingerprintJob.kt:148-151`) retries forever with exponential backoff; each attempt is a full-file MediaCodec decode (10-min timeout, `OnsetExtractor.kt:149`) + Silero VAD pass. A poisoned file drains battery for days. Cap with `runAttemptCount` → `failure()` after e.g. 3.
23. Auto sidecar pick disagrees between playback (name match, `SubtitleSourceResolver.pickAutoSidecar:136-145`) and the fingerprint job (score-based, `SyncFingerprintJob.kt:274-285`) — with 2+ sidecars the persisted lock can be fitted to a different file than the one rendered. Share one picker.
24. `AudioSyncProcessor` analyzes only `ENCODING_PCM_16BIT` (`:78-86`) — float-passthrough devices get silently no sync; and `windowSamples = ShortArray(320)` (`:41`) truncates the analysis window to 320 samples at >32 kHz (3.3 ms @48 kHz stereo instead of 10 ms), degrading features. The per-window `take/map/map` allocations (`:140-153`) also belong off the audio thread (see 6).
25. `PlaybackEngine.play()` suspends for the Room read between `setMediaItem/prepare` and `seekTo(saved)` (`PlaybackEngine.kt:266-277`) → brief frame-0 flash on resume; read the position before `setMediaItem` (or pass it in).
26. `requestDecoderRebuild` clears `isRebuildingDecoder` after a fixed 800 ms (`PlayerActivity.kt:581-585`) despite the doc claiming it waits for STATE_READY; on slow storage the chip unblocks too early. Drive it from the player listener.
27. `openVideo` failure path only logs (`PlayerActivity.kt:532-535`) — user sees a black screen with no error surface (`errorMsg` is fed only by `onPlayerError`).

### Media3 / UX polish
28. Debug diagnostics overlay ships in the UI: `PlayerScreen.kt:1524-1541` renders `state=… pos=… video=…` whenever state ≠ READY — i.e. during every normal buffering phase. Gate behind a debug flag or delete.
29. `SubtitleStyleSheet` changes are invisible: `subStyle` (`PlayerActivity.kt:159,412-416`) is never passed to `PlayerScreen`, which renders from its own `subSize/subPos/subColor` state (`PlayerScreen.kt:1122-1124`). Also the subtitle box has two competing long-press handlers (`pointerInput` menu at `:1411-1446` + `combinedClickable` at `:1447-1453`), and `showSubtitleMenu` is written but never read. Pick one system.
30. Audio track choice not persisted/restored: `onAudioTrackSelected` (`PlayerActivity.kt:640-673`) never calls `stateStore.updateAudioTrack` (exists at `MediaStateStore.kt:38-41`, unused) and `openVideo` never re-applies it. The `TrackSelectionOverride` usage itself is correct.
31. PiP: fixed 16:9 aspect regardless of the video (`PlayerActivity.kt:542-544, 796-800`) — letterboxed 2.35:1 content; use the real aspect (or `setSourceRectHint`). `enterPictureInPictureMode` is unguarded (`:540-547`) and can throw `IllegalStateException` (already-in-PiP / non-resizable window).
32. `MediaRouter` discovery with `CALLBACK_FLAG_REQUEST_DISCOVERY` runs for the whole activity lifetime (`PlayerActivity.kt:245-249`) — continuous Cast/BT scanning; add the callback only while the picker is open (the sheet already manages its own callback, `CastRoutePickerSheet.kt:77-99`).
33. Per-open full MediaStore scans: `EpisodeQueue.build` re-runs `MediaScanner.scan()` (whole Video table) on every open/switch (`EpisodeQueue.kt:61-67`, `MediaScanner.kt:63-100`), and sidecar listing pulls every subtitle row device-wide then filters folders in Kotlin (`SubtitleSourceResolver.kt:105-125`). Cache the library snapshot (you already observe it) and add a `DATA LIKE` folder filter.
34. `POST_NOTIFICATIONS` is requested cold in `PlayerActivity.onCreate` (`PlayerActivity.kt:216-220`) with no rationale and the deprecated `requestPermissions` API; move to the point of need (service start) with an explanation.
35. `OnsetExtractor.resolveFfmpegPath` will execute any `ffmpeg` found on `PATH` or `/data/local/tmp` (`OnsetExtractor.kt:375-393`) — an arbitrary-binary surface; and `runProcess` drains stdout fully before stderr (`:397-415`) — theoretical pipe deadlock. Prefer the app-files binary only; read streams concurrently.
36. `OpenSubtitlesClient` targets the legacy XML-RPC endpoint with guest login (`OpenSubtitlesClient.kt:27,127-140`) — that API has been deprecated/sunset in favor of the keyed REST API; expect this feature to stop working (or already be dead). Plan migration or label it experimental.
37. Dead code with teeth: `settingsProvider` (`PlaybackEngine.kt:48`) is never used, but its supplier is `runBlocking { settingsFlow.first() }` (`AnonrodeApp.kt:35`) — if anyone wires it up on the main thread, instant ANR. Delete both. `MediaStateStore.pruneMissing` (`:108-113`) is also unused — good, because feeding it a partial/failed scan would mass-delete watch history; keep it that way until it can be made safe.
38. `PlayerPrefs` keys grow unboundedly (`sub_pos_<uri>` per video, `PlayerPrefs.kt:23-37`) — SharedPreferences file bloats forever; prune or move to Room.
